### 16.4 唯一结论：Gitee Pages 部署目录 = `source/ai-drama-studio/web-app`

**结论（唯一，不两头下注）**：部署分支 `main`，**部署目录填 `source/ai-drama-studio/web-app`**，Build command 留空；访问 `https://jiang-ling1023.gitee.io/ai-drama-studio/` 即以该目录下的 `index.html` 为站点根文档。

| 约束 | 满足方式 |
| --- | --- |
| Pages 能识别入口 | 该子目录内存在唯一 `index.html`；主理人已核实 Gitee Pages「部署目录可指定（根或子目录）」 |
| 工程宝 `web-app/` 分层 | 源码恰在 `source/<项目名>/web-app/`，与工程宝 `source/safety-repair-system/web-app/` 及 DEPLOY.md「Build output 填 web-app」完全同构 |
| §11a 相对路径 | 部署后子目录即站点根，`css/style.css`、`js/app.js` 解析为 `.../ai-drama-studio/css/style.css`，无需 `<base>`、无需 `/` 开头绝对路径 |
| 零构建 | 目录内即提交物即可执行静态资源，无任何 build 命令、无 CI 产物 |

**根 `index.html` 不需要存在**。Gitee Pages 指定部署目录后，仓库根不再是站点根；放根 `index.html` 只能做跳转页或复制第二份应用，二者都制造第二份入口（违反 G-1）并额外引入重定向。故仓库根**不放** `index.html`、**不放** `assets/`、不放任何站点文件；用户从 README 的在线地址进入，仓库根只有文档、脚本、成品包与 `source/`。工程宝忽略 `source/.../web/`：那是它的**产物目录**，本项目 `web-app/` 是**必须提交的源码**，`.gitignore` 中**绝不可**出现 `web-app/` 或 `source/`（16.2 #2 最易踩的坑）。

### 16.5 冲突处理：工程宝全局脚本 vs 第一块 §11c ESM

**冲突**：工程宝 `web-app/index.html` 用多个 `<script src="js/xxx.js">` 经典全局脚本；第一块 §11c 冻结「同源 HTTP(S) 原生 ESM、import 相对且带 `.js` 后缀、**不退回全局 script**」，§15 已将其列为冻结项。
**唯一落地方式（保持契约 + 调整加载方式，不推翻契约）**：
- `index.html` 保留 `<link rel="stylesheet" href="css/style.css">` 相对引用不变；
- 入口改为**单个** `<script type="module" src="js/app.js">`，删除全部经典 `<script src>`；
- 其余 `js/**/*.js` 一律 `export` / `import ... from './相对路径.js'`，带 `.js` 后缀；
- `css/style.css` 单一文件承载全部视觉 token（§11f），不是工程宝的多脚本拆法。
**为何不推翻第一块**：§11c 的结论建立在「同源 HTTPS」而非 `file://` 之上，Gitee Pages 恰好提供同源 HTTPS，前提更充分，无理由改；G-3 冻结即冻结，开发期间不得偏离。用户 7 条规范中第 3 条约束的是「相对路径 + 中文编码 + 容器」，并未强制全局脚本——经典 `<script>` 是工程宝自身的历史实现细节，不是规范条款。**目录形状（`web-app/` 下 `index.html`/`css/`/`js/`）与工程宝完全一致**，仅脚本 `type` 与模块间引用方式不同，属路径/加载层调整；第一块 §12 数据模型、§13 模块 API、§14 调用链、§15 冻结清单逐字不动。
