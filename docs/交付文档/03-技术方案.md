## 1. 技术选型与运行架构决策

### 1.1 单一决策：**选 A — 纯前端零部署（本地静态文件 + localStorage 持久化）**

不引入任何业务后端、不引入 Python/Node 运行时代码、不引入服务端进程。唯一需要的外部程序是系统自带的静态文件服务器（只提供 http 协议，不含任何业务逻辑）。

### 1.2 六条理由

| # | 理由 |
| --- | --- |
| 1 | **零安装、零进程**：用户是非工程师创作者。B 要求安装 Python、保持终端进程存活、理解端口与关闭终端即不可用的后果；A 是一条静态服务器命令 + 一个浏览器标签。R-01「浏览器可直接打开使用」在 A 下判定成本最低 |
| 2 | **零密钥 12 步可连续走通**：全部演示数据编译为前端 JS 常量，离线可用、无需联网、不依赖任何常驻进程；B 把「必须有一个活着的后端」变成主链路单点，进程挂则 S-02 断 |
| 3 | **数据仅存本地的最小面**：localStorage 在浏览器沙箱内，天然不出设备（R-04/K-04）；B 把工程落盘成磁盘文件、把密钥移进后端进程内存，仍是本机明文，安全性未提升，却新增「后端日志/临时文件」泄漏面（K-03） |
| 4 | **B 的三项收益在本约束下均非必需**：① 代理模型 API — 目标地址由用户自填 Base URL，浏览器直发即可，跨域用可配置代理解决（1.4）；② 密钥保管 — K-01 明确密钥「仅保存在本地模型配置中」，本就应留浏览器；③ 工程落盘 — localStorage + 导出文件已满足 R-03/R-05。为三件可省的事引入整套进程模型属过度设计（G-1） |
| 5 | **并行开发无需前后端联调**：11 页均为「读同一个 Project → 改同一个 Project → 重渲染」，后端 CRUD 是纯透传、无业务价值；A 下多人并行只需约定文件路径与导出名，契约冻结面收窄为一层 |
| 6 | **交付与分发**：A 是一个目录，可 zip 分发、可任意静态托管、可离线；B 是「目录 + 启动脚本 + 运行时 + 端口」，S-02「不依赖外部工具」难以客观判定 |

### 1.3 被弃方案 B 的代价（明确承认）

| 代价 | 说明 |
| --- | --- |
| 用户门槛 | 需 Python ≥3.8 且终端常驻；Windows 无 Python 或杀软拦截 `.py` 时直接不可用 |
| 运行脆弱 | 端口冲突、防火墙提示、终端关闭即服务终止；非工程师无法自恢复 |
| 代码与契约翻倍 | 第二套语言 + 一套 HTTP 接口契约 + 前后端联调；本次「接口契约」将凭空多一层透传层 |
| 安全面扩大 | 密钥经后端转发，日志/异常/临时文件均可能留痕（K-03 风险上升），而防护级别不变 |
| 交付复杂度 | 工程数据从「一个 JSON」变为「文件 + 后端写入路径」，E-17/E-18 的判定与备份恢复实现更复杂 |

> 结论：B 唯一能解决而 A 需要额外说明的是「跨域」，该项在 1.4 用「用户自填 Base URL + 可选 CORS 代理」覆盖，且默认零配置路径**完全不发网络请求**，不影响 S-02。

### 1.4 选 A 必答五问

**① `file://` 直接打开 `index.html` 能否运行：不能。** ES module 在 `file://` 下 origin 为 `null`，Chrome/Edge/Firefox 均按 CORS 拒绝加载同目录 `.js`（控制台报 module 脚本跨源错误），且 `fetch` 读本地文件同样被拒。**唯一启动命令**（在项目根目录执行，零第三方依赖、零业务后端、零安装）：

  ```
  python3 -m http.server 8080
  ```

随后浏览器打开 `http://localhost:8080/`。Windows 上 `python3` 的等价别名为 `py`（`py -m http.server 8080`），属同一条命令。该进程只负责把静态文件以 http 同源提供，不含任何模型代理、密钥保管或工程写入逻辑。
**② ES module 的 CORS 规避**：
- 全部资源经 `http://localhost:8080` **同源**加载，`index.html` 仅保留一个 `<script type="module" src="./src/main.js">`，其余模块全部走 import 图；
- import 路径一律 `./` 或 `../` 相对路径且**必须写全 `.js` 扩展名**（浏览器原生 ESM 不做后缀补全）；不使用 import maps、不使用裸模块名；
- **演示数据、文案常量、枚举一律编译为 `.js` 导出常量，不使用 `.json` + `fetch()` 读取本地配置**，因此应用运行期不存在任何本地 XHR 请求；
- 不为兼容 `file://` 而退回全局 `<script>` 命名空间：模块边界是「单一公共模块、禁止各写各的提示词组装器」（G-1）的技术前提，全局命名空间无法保证 import 唯一来源。
**③ 模型请求跨域与可配置代理**：
- 唯一发网出口是 `core/model-adapter.js` 的 `fetch`，使用 `mode:'cors'`、`credentials:'omit'`，`Authorization` 头只发往该条 `ModelConfig.Base URL`（K-01）；
- 目标服务未返回 CORS 响应头时浏览器拦截，适配层按 D-01 捕获为「网络中断/响应非法」，任务降级演示数据并写可读错误（E-06），**不阻断流程**；
- **可配置代理不新增字段、不内置代理服务**：用户把 `Base URL` 填为自己运行的任意 CORS 代理地址（如 `http://localhost:8081/agnes`），适配层只认这一个地址。这样既不违反第 5 章 ModelConfig 字段冻结，也不引入第二个进程作为交付前置；
- 未配置 / 未启用 / 强制演示数据开启时**一个网络请求都不发**，故 CORS 永远不影响零密钥主链路。
**④ 离线演示数据的图片/关键帧**：一律**内联 SVG dataURL**，禁止外链图片（禁 `<img src="https://">`、禁 CDN 图标、禁 CSS 外链背景、禁字体外链）。`demo/demo-image.js` 按「资产ID / 分镜ID + 帧类型」确定性生成同一张固定 SVG（同 ID 永远同图，满足 D-04 可复现），返回 `data:image/svg+xml;charset=utf-8,` + `encodeURIComponent(svg)`。所有图片引用类字段（`图片引用`、`输出引用`、`关键帧图引用`、`参考图引用`）**存 dataURL 字符串，不存 Blob URL**（Blob URL 刷新即失效，会破坏 R-03 保存恢复与导出）。用户上传的参考图用 `FileReader.readAsDataURL` 同样转 dataURL。「演示数据」斜纹角标由 C-03 叠加在预览层，不烧进图片；「缺失帧」是 `图片引用 === ''` 时的灰色占位，不伪造图片。
**⑤ localStorage 容量超限与导出/导入**（详见第 4 节，此处给结论）：单 value 约 5MB 量级，而剧本上限 50,000 字（A-03）约 100KB、单张内联 SVG \< 2KB，正常工程远低于限额；风险仅来自用户上传的大图，故 `FileImport` 对图片做体积上限校验并提示压缩。写入采用**主/备双键 + try/catch `QuotaExceededError`**：先写备份键再写主键，超限时不覆盖旧值、状态保持原值、常驻错误 Toast（E-18）。导出走 `Blob + URL.createObjectURL + <a download>`，导入走 `FileReader` + 校验 + 就地 `hydrate`，二者**不经过服务器**，导出文件本身即备份与迁移载体（R-05）。

### 1.5 技术栈清单

| 层 | 技术 | 版本 / 基线 | 选型理由 |
| --- | --- | --- | --- |
| 运行 | 原生 ES module（ES2020）+ 浏览器 DOM | 无框架、无构建、无 npm | 一条静态命令即可跑；模块边界由 import 图保证 |
| 语言 | JavaScript（运行时）；TS 风格 interface 仅作**契约文档** | ES2020 | 若真用 TS 需 `tsc`/构建步骤，违反零构建与浏览器直开；契约用 interface 表达但不产生编译产物 |
| 渲染 | 模板字符串 + `innerHTML` 局部重绘 + 事件委托 | 原生 | 11 页均为表格/表单/状态标签，无高频更新与复杂组件树 |
| 样式 | 原生 CSS 变量（第 7 章深色基调） | CSS Variables | 无预处理器、无 CDN、离线可用 |
| 存储 | `localStorage`（工程主/备、UI、密钥四键分离） | 浏览器原生 | 单工程、单用户、无并发写；整体 JSON 即保存单位 |
| 文件 IO | `Blob`/`URL.createObjectURL`/`FileReader` | 浏览器原生 | 导出导入零服务端 |
| 网络 | 原生 `fetch` + `AbortController`（超时） | 浏览器原生 | 仅用户自填 Base URL；无 SDK、无第三方包 |
| 图片 | 内联 SVG dataURL | — | 离线、可持久化、可随工程导出 |
| ID / 时间 | 自实现 `uid()` / `Date.toISOString()` | — | 不引入 uuid/dayjs 等依赖 |
| 静态服务 | `python3 -m http.server 8080` | 系统自带 | 零安装、零业务代码、只提供 http 同源 |

### 1.6 为什么不用构建工具 / 为什么不用框架

**不用构建工具**：① 构建需 `npm install` + 构建命令，用户是非工程师且约束「浏览器可直接打开」；② 会引入 `node_modules`、打包配置、锁文件，交付从「一个目录」变「一套工程」；③ 原生 ESM 已提供 11 页 + 13 组件 + 9 基础模块所需的模块边界；④ 契约冻结后并行开发靠文件路径约定，打包器不解决契约问题；⑤ 源码可直接审阅修改，符合「直接落代码」。
**不用框架**：① 页面形态是表格/表单/列表 + 状态标签，原生 DOM 足够；② 框架需运行时与编译（JSX），CDN 引入又违反离线禁外链；③ 框架的响应式 state 会与「唯一 Project 引用」形成两套状态，极易产生副本，直接违反产品 1.4「任何页面不持有副本」与 G-1；④ 视图切换只替换主工作区 DOM 子树、成本极低，不需要虚拟 DOM；⑤ 无版本升级与兼容矩阵维护。

### 1.7 浏览器兼容基线

Chrome / Edge ≥ 90、Firefox ≥ 90、Safari ≥ 15（需支持：ES module、可选链、CSS 变量、`Blob`/`FileReader`、`localStorage`、`fetch` + `AbortController`）。**仅桌面、最小宽度 1280px**（A-10）；不承诺移动端、不兼容 IE、不提供多浏览器矩阵。\<1024px 显示常驻提示条但功能可用。

### 2.2 「单一 Project 引用 + 失焦即写回 + 视图切换不重建」落地方式

1. `main.js` 调 `loadProject()` 得到唯一对象，`app.js` 以模块级 `let project` 持有，**只导出 `getProject()`**；全应用禁止第二处 `createEmptyProject()`、禁止深拷贝工程、禁止页面持有副本。M-001、任务面板、C-12 全部读同一引用。
1. 写路径唯一：`store.commit(mutator)` 就地修改 `getProject()` 的子集合条目（按 ID 查找后赋值）。C-02 `EditableRow.onCommit` 在 `blur`/`change` 时直接 commit，**不依赖保存按钮**；多行文本框在 `blur` 与视图切换前由 `workspace` 触发一次 commit，不静默丢弃。
1. 视图切换 = `workspace.setView(pageId)` 仅替换主工作区 DOM 子树，`project` 引用不变、不重新 load、不重建对象；每个页面 `render()` 每次从 `getProject()` 现读，故重新进入必读到写回后的值（产品 1.4 / F-002 验收）。滚动位置可缓存于 UI 键，**工程数据不缓存**。
1. commit 后 `store.markDirty()` → 顶部状态追加「· 有未保存更改」→ 防抖 300ms 落盘；显式「保存」立即落盘并置「已保存」；`beforeunload` 兜底一次落盘。
1. 覆盖/删除/解锁/全量重建/新建工程统一走 C-04，取消时内存数据不变（不回滚、不克隆）。

### 3.1 冻结口径（三条，开发照此执行）

### 3.5 为什么关系型 SQL 不适用

1. 单用户、单工程、无并发写、无跨工程查询，全部数据是一棵对象树，**保存/恢复/导出的单位就是整份 JSON**；拆成 12 张表只会带来 JOIN 与重组，没有任何查询收益。
1. 浏览器内无内置 SQL 引擎；引入 SQLite/wasm 或后端数据库等于引入构建、运行时或进程，直接推翻 1.1 决策与零依赖约束。
1. 工程结构由「嵌套子集合 + 引用 ID」表达，正是文档数据库形状；`createEmptyProject()` 已完整定义每个集合的初始形状与外键语义（引用 ID 由 `derive.js` 做悬空校验，E-16 级联清理），无需额外 schema 层。
1. 版本迁移只需对一份 JSON 补字段（4.5），比 12 张表的 DDL 迁移更可控，符合「最小可用即可」。

## 4. 持久化与工程 IO 设计

### 4.1 存储键与函数签名（冻结，第二块给实现契约）

| 键 | 内容 |
| --- | --- |
| `PROJECT_KEY` | 工程主槽：完整 Project JSON（`保存状态` 随工程一起写） |
| `BACKUP_KEY` | 上一次可用工程 JSON（每次成功保存前由主槽复制，E-17 恢复源） |
| `UI_KEY` | UI 态：当前步骤、各视图滚动位置、抽屉开合；**不随工程导出** |
| `SECRETS_KEY` | `{ [配置ID]: 'API Key' }`；密钥与工程物理分离 |

  ```js
  // src/core/storage.js

  export function loadProject(): { project: Project; status: 'ok' | 'damaged' | 'empty' };
  export function saveProject(project: Project): { ok: true } | { ok: false; reason: 'quota' | 'unknown'; usedBytes: number };
  ```

### 4.2 保存 / 恢复 / 导出 / 导入流程

- **保存**：`commit()` 就地改内存 → `markDirty()`（顶部追加「· 有未保存更改」）→ 防抖 300ms `saveProject()`；显式保存与 `beforeunload` 走 `saveNow()`。`saveProject` 写入顺序固定为「主槽旧值 → BACKUP\_KEY」再「写 PROJECT\_KEY」，成功后置 `保存状态='已保存'`。
- **恢复**：`main.js` → `loadProject()`；`status='ok'` 时 `migrate` 后把 `保存状态` 置为 `已恢复`（内存态，不立即回写以免覆盖备份），`hydrate()` 后各页 `render()` 现读，11 类对象条目数与保存前一致（S-03）。`status='empty'` → `createEmptyProject()` 落 P-001 空态，状态 `新建`。
- **导出**：`exportFile()` 内部强制三步 `stripSecrets → JSON/CSV 序列化 → validateNoKey`，任一步失败即中止下载并报错。分镜表、片段清单(JSON/CSV)、工程包、导出工程**全部经此唯一出口**，禁止任何页面自行 `JSON.stringify(project)` 后下载（G-1）。产物为纯文本结构化文件，无私有二进制、无真实编码文件（VID-05 / K-02）。
- **导入**：`FileImport` → `importProject(file)`（FileReader → JSON.parse → `migrate` → `validateProject`）→ 成功则 `hydrate(project)` **就地覆盖同一引用** + `saveProject()` + 状态 `已恢复` + 全量重渲染（等效全页刷新，但不新建第二个 Project 引用、不丢 UI 态）；失败按 E-17 弹 C-04，**不覆盖原工程**。

### 4.3 密钥剥离落地点（K-02 / E-19）

| 落点 | 唯一实现 | 动作 |
| --- | --- | --- |
| 持久化写入 | `saveProject()` | 序列化前把每条 `modelConfigs[i]['API Key']` 抽出到 `SECRETS_KEY`（键=配置ID），**工程 JSON 中删除该键**；工程主/备槽永不出现密钥 |
| 读取回填 | `model-adapter.js` | 仅发起请求时按配置ID 从 `SECRETS_KEY` 取密钥注入 `Authorization`，且只发往该条 `Base URL`（K-01） |
| 导出 | `io.exportFile()` → `stripSecrets()` → `validateNoKey()` | 双保险：即使工程对象内存态临时含密钥，导出仍递归删除 `'API Key'` 键并校验序列化串不含键名与已知密钥值，通过才下载 |
| 禁止面 | 全局 | 密钥不进 `GenTask.输入快照` / `最终提示词快照`、不进日志、不进演示数据、不进任何导出物、界面默认掩码（K-03） |

> 由于工程槽与导出物**结构上就不含密钥**，「导出文件已校验：不含 API Key」是可客观判定的结论，不依赖使用者记得勾选。

### 4.4 E-17 数据损坏 / E-18 容量超限

- **E-17**：`loadProject()` 对主槽 `JSON.parse` 失败或 `validateProject` 失败 → `status='damaged'`，**不写回、不删除原始字符串**；`main.js` 用 `createEmptyProject()` 造内存占位仅供壳层渲染，状态置 `损坏`，弹 C-04 变体（默认焦点「取消」）：选「恢复上一次可用数据」读 `BACKUP_KEY` 并 `migrate`；选「新建工程」才调用 `createEmptyProject()` + `saveProject()` 覆盖主槽。全程原始数据可恢复。
- **E-18**：`saveProject()` 用 try/catch 捕获 `QuotaExceededError`（含 Safari 私有模式写入异常），先写备份再写主槽，主槽写失败时旧值仍完整保留、状态保持原值、返回 `usedBytes`；UI 出常驻错误 Toast「本地存储空间不足（当前占用 X），建议先导出工程备份再清理数据」，**不静默丢弃数据**。`FileImport` 对参考图设体积上限并在超限时给出可读提示，从源头降低膨胀概率。

### 4.5 版本号与迁移策略（最小可用）

- `SCHEMA_VERSION = 1`，随工程写入 `schemaVersion` 字段；不建迁移框架、不预留抽象层。
- `migrate(raw)` 只做三件事：① 无 `schemaVersion` 字段 → 视为 v1，按 `createEmptyProject()` 的形状**逐字段补默认值**（不覆盖已有值），保证旧工程可读；② `schemaVersion === 1` → 校验后原样返回；③ `schemaVersion > 1` → 返回拒绝，导入报 `reason='version'` 并提示工程文件版本高于当前工作台，**不静默降级、不丢数据**。
- 未来新增版本时，仅在 `migrate` 内增加一个 `if (v === 1) { ...; v = 2 }` 分支，不改动任何页面代码。

## 6. 模型适配层调用契约与降级状态机

### 6.1 统一入口与按「用途」选配置

`callModel(project, usage, payload)` 是**全应用唯一发网出口**。`selectConfig` 规则：① `isForceDemo(project)` → 返回 null（零请求）；② 过滤 `启用状态 === true && 用途 === usage`；③ 文本任务优先 `来源类型='agnes-ai 文本'`、媒体任务优先 `'agnes-ai 媒体'`，`'自定义'` 按 `用途` 归入同类排序；④ 同类多条按 `配置ID` 字典序取第一条；⑤ 无结果 → null → 演示数据。API Key 由 `storage` 按配置ID 从 `SECRETS_KEY` 读出后注入，不进入 `ModelResult`、不进入任何快照。

### 6.2 请求 / 响应约定（OpenAI 兼容风格，可替换）

  ```js
  // 文本（F-001/002/003/005）：POST `${Base URL 去尾斜杠}/chat/completions`
  { model: cfg['模型名称/ID'],
    messages: [{ role:'system', content:'你是短剧编剧助手，只返回结构化文本' },
               { role:'user', content: payload.messages?.[0]?.content ?? payload.input }],
    temperature: 0.7, stream: false }
  // 取 choices[0].message.content（字符串），做非空校验；取不到 → BAD_RESPONSE

  // 取 data[0].b64_json → 'data:image/png;base64,' + 值；缺失/类型不符 → BAD_RESPONSE
  // 公共：Authorization: Bearer <API Key>；Content-Type: application/json；mode:'cors'；credentials:'omit'
  ```

三类来源共用这两个模板，仅 `来源类型` 影响选中优先级。可替换点：`registerAdapter(sourceType, adapterFn)` 覆盖 `buildRequest` / `parseResponse`；**真实 agnes-ai 接口文档到位后只改 `core/model-adapter.js` 内的 `DEFAULT_ADAPTERS` 注册表与解析函数**，其余文件零改动；自定义端点结构不同时同样只在此注册，不新增模块。

### 6.3 超时、降级状态机与错误映射

  ```js
  // callModel 内部流程（伪代码；注释只标关键边界，说明「为什么」）
  if (isForceDemo(project)) return { ok:false, errorCode:'FORCE_DEMO', sourceMark:'演示数据', latencyMs:0 };
  const cfg = selectConfig(project, usage);
  if (!cfg) return { ok:false, errorCode:'NOT_CONFIGURED', ... };
  const ac = new AbortController();
  const timer = setTimeout(() => ac.abort(), (cfg.超时阈值 || 30) * 1000);  // 达阈值即终止，不无限挂起（E-05）
  try {
    const res = await fetch(url, { signal: ac.signal, ... });
    if (!res.ok) throw mapHttp(res.status);              // 401/403/429/5xx → 可读错误
    const data = parseResponse(await res.json());        // 格式非法不写脏数据
    return { ok:true, data, sourceMark: cfg.来源类型, latencyMs };
  } catch (e) {
    return { ok:false, errorCode:e.code, message:可读文案, sourceMark:'演示数据', latencyMs };
  } finally { clearTimeout(timer); }                      // 必须清理，避免定时器泄漏
  ```

| D 规则 | 代码落点 |
| --- | --- |
| D-01 真实优先 | `selectConfig` 有可用配置才 fetch，否则 `getDemoFallback` |
| D-02 降级可见 | `genTask.settleTask` 写 `状态='已降级(演示数据)'`、`来源模型标识='演示数据'`；C-03 角标 |
| D-03 不阻断 | `callModel` **永不向页面抛异常**，统一返回 `ok:false`；`runTask` 后流程继续 |
| D-04 固定样例 | `demoFor()` 顶层常量，零随机 |
| D-05 全局开关 | `isForceDemo` 在 `callModel` 第一行短路，`fetch` 调用次数 = 0 |
| D-06 重试幂等 | `retryTask(taskId)` 复用同一任务与产物槽，只覆盖 `输出引用`，不追加 KeyFrame/StoryboardItem |

| 情况 | errorCode | 可读文案（统一追加「流程可继续」） | GenTask 状态 |
| --- | --- | --- | --- |
| 401/403 | `AUTH` | 密钥无效或权限不足，请检查模型配置 | 已降级(演示数据) |
| 429 | `RATE_LIMIT` | 模型请求被限流，已使用演示数据，可稍后重试 | 已降级 |
| 5xx | `SERVER` | 模型服务暂时不可用，已使用演示数据 | 已降级 |
| 网络中断 / CORS 拦截 | `NETWORK` | 网络连接不可用 | 已降级 |
| 超时 | `TIMEOUT` | 请求已超时（阈值 X 秒），已终止等待并使用演示数据 | 已降级（记录耗时） |
| 响应非法 | `BAD_RESPONSE` | 模型返回格式异常，已使用演示数据，未写入异常数据 | 已降级 |
| 未配置/未启用 | `NOT_CONFIGURED` | 未配置模型，当前使用演示数据 | 已降级 |
| 强制开关 | `FORCE_DEMO` | 已强制使用演示数据，不会向任何模型地址发起请求 | 已降级（展示「演示数据（强制）」） |

> 状态口径：**模型类失败一律 `已降级(演示数据)`**；`失败` 仅用于本地非模型错误（数据源读取失败、组装失败）。二者均可重试；重试成功转 `成功`，仍失败保持原态且 `重试次数 + 1`，不插入重复产物（E-07）。错误一律写 `GenTask.错误信息`，界面不显示原始堆栈。

## 7. 提示词组装器（ANC/NEG 唯一实现）

`buildPromptSnapshot(ctx)` 输入见 5.2 `PromptBuildContext`，输出为第一块 3.2 的 `PromptSnapshot`（正向 / 负面 / 来源标记三区），**由 `genTask.createTask()` 唯一调用并在创建瞬间冻结进 `GenTask.最终提示词快照`**。

  ```js
  function buildPromptSnapshot(ctx) {
    const p = ctx.project, ps = p.promptSet;
    // ANC-01/02/04：只注入「已锁定」人物锚点；未锁定/无锚点不注入，缺失清单由 derive 出，不阻断
    const anchors = (ctx.关联资产ID列表 || [])
      .map(id => p.assets.find(a => a.资产ID === id && a.类型 === '人物' && a.锁定状态 === '已锁定'))
      .filter(Boolean);
    const anchorRefs = anchors.map(a => ({ 资产ID:a.资产ID, 锚点标识:a.锚点标识,
      外貌描述:a.外貌描述, 服装描述:a.服装描述, 特征描述:a.特征描述, 参考图引用:a.参考图引用 }));
    // ANC-03：锚点 > 单条同类描述；冲突词不生效，记入「被锚点覆盖」供 C-12 判定
    const covered = diffConflict(ctx.单条正向词 || '', anchors);
    const 正向 = { 全局正向词: ps.全局正向词, 角色锚点: anchorRefs,
                   单条正向词: stripCovered(ctx.单条正向词 || '', covered), 被锚点覆盖: covered };
    // NEG-02/04：全局锁定词 ∪ 单条词去重；单条声明移除锁定词时忽略，锁定词必定保留
    const locked = ps.负面词锁定状态 === '已锁定' ? dedupe(ps.锁定词快照) : [];
    const single = dedupe(ctx.单条负面词 || []);
    const 负面 = { 全局锁定负面词: locked, 单条负面词: single.filter(w => !locked.includes(w)) };
    // NEG-01：文本类任务不参与负面词锁定，C-12 负面区标注「本任务不适用负面词锁定」
    const 文本类 = ctx.taskType === '文本';
    // ANC-05/NEG-01/NEG-05：快照只读冻结，此后锁定/解锁/编辑不回写历史任务
    return { 正向, 负面: 文本类 ? { 全局锁定负面词:[], 单条负面词:[] } : 负面,
             来源标记: { 来源模型标识: resolveMark(p), 输入快照摘要: ctx.对象ID,
                          组装规则版本: 'v1', 不回溯: true, 文本类不适用: 文本类 } };
  }
  ```

| 规则 | 落地 |
| --- | --- |
| ANC-01/02 | 按单个角色读 `AssetAnchor` 六字段；涉及角色即自动携带描述+锚点标识+参考图，F-006/007/010 共用 |
| ANC-03 | `diffConflict` 标记冲突词 → `被锚点覆盖[]`，锚点描述生效、冲突描述不生效（E-10） |
| ANC-04/06 | 无锚点不阻断，缺失清单由 `derive.missingAnchors` 出；正向侧与负面侧并行，互不覆盖 |
| ANC-05 | 快照在 `createTask` 冻结；解锁/编辑后历史快照深比对不变 |
| NEG-01 | 仅此后新发起任务调用本函数；文本类任务负面区标注不适用 |
| NEG-02/03/04 | `union(锁定词快照, 单条词)` 去重；`rejectLockedWordRemoval()` 对删除/置空/覆盖/注释返回原句 `该负面词已被全局锁定，不可移除` 并复位输入；`appendShotNegative()` 仅追加去重 |
| NEG-05 | 解锁只改 `ps.负面词锁定状态` 与 `解锁时间`，**不删除 `锁定词快照` 词文本**；历史快照不变 |
| NEG-06 | C-12 三区 + 以下断言可逐任务验证 |

**「锁定词出现率 100%」可验证断言点**（直接对 `project.genTasks[i].最终提示词快照` 断言）：
- `A1` `locked.every(w => snap.负面.全局锁定负面词.includes(w)) === true`（NEG-02/06、S-04）
- `A2` `new Set([...snap.负面.全局锁定负面词, ...snap.负面.单条负面词]).size === 两者长度之和`（并集无重复）
- `A3` 单条任务写入「移除 X」且 X∈locked 时，`snap.负面.全局锁定负面词` 仍含 X（NEG-03/04、E-11）
- `A4` 类型∈{图片,关键帧} 且 `关联资产ID列表` 含已锁定人物 → `snap.正向.角色锚点` 含该 `锚点标识` 与三项描述（ANC-02、S-04）
- `A5` 解锁或编辑锚点前后，历史任务快照 JSON 深比对相等（ANC-05/NEG-01、E-12）

> 禁止任何页面重写本函数；F-006/F-007/F-010 的结果差异只来自 `ctx`（对象ID、关联资产、帧类型、单条词），不来自第二套组装逻辑。

### 8.2 `demo-image.js` SVG 规则与 dataURL 格式

- 确定性：`seed` 字符串做 FNV-1a 哈希 → 色相 / 几何参数 / 构图；**同 seed 永远同图**，不使用随机数或时间。`demoKeyFrame` 以 `分镜ID + '|' + 帧类型` 为 seed，首帧/尾帧几何不同且可复现。
