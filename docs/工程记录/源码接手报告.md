## 四、60 条手工验收清单怎么处理

`docs/验收报告-可判定清单.md` 有 **60 条 `- [ ]` 手工断言，当前 0 条勾选**，验收结论表四项全是「待填」。

其中**两项自动检查我现在就能给出结论**（见 3.1 / 3.2），可填：

| 项 | 可填值 |
|---|---|
| 自动检查 `bash scripts/check-static.sh` | **5 项全 PASS，退出码 0** |
| 自动检查 `node scripts/check-contract.mjs` | **15 项全 PASS，退出码 0** |
| 手工清单通过数 | 待填 / 共 60 条 |
| 结论 | 待填（自动检查已通过，手工 60 条未执行） |

**我没有直接改仓库里的那份文档**，原因有两个：

1. `src/repo` 是干净的上游克隆，改动会让 `git status` 变脏，日后 `git pull` 容易冲突；
2. 剩下 60 条手工断言需要**在浏览器里逐条点**（刷新恢复、动效开关、Network 面板核对等），不该由我凭代码推断勾选——那是伪造验收。

## 六、接手过程中顺手修掉的工具缺陷

这一轮是 `tools/ingest.sh` **第一次接触真材料**，立刻暴露 4 个此前测不出来的问题，全部已修（详见 `docs/工具自测报告.md` 第九节）：

| 缺陷 | 表现 | 修法 |
|---|---|---|
| `du -h` 作用于目录 | 【1】体积行刷出 30 多行子目录数字 | 目录改用 `du -sh` |
| 未排除 `.git` | `.git/hooks/*.sample` 让「30 个无扩展名 + 14 个 .sample」占据扩展名榜首，真源码被淹 | find 排除 `.git` / `node_modules` / `dist` / `build` / `__pycache__` |
| 清单深度只有 4 | `source/ai-drama-studio/web-app/js/pages/p001.js` 是第 5 层，**整层源码被截断** | 深度提到 6 |
| hash 正则过宽 | `director` / `keyframe` / `assembly` / `response` / `timeline` / `download` 都是 8 字母，被当成 Vite hash → **真项目被判 `fail`** | 要求 8 位且大小写混合；纯小写 kebab-case 不再算负面信号 |
| 不认识 `source/` `web-app/` | 源码目录特征未命中 | 特征扩为 `src/ · app/ · source/ · web-app/`，并补 `index.html`、`js/+css/`、`pages/components/shell`、功能说明/验收报告等 6 项 |

修复前后对同一份真材料的判定：

```
修复前：判定 ❌ 不像工程包（仅 1 项特征命中，负面信号 0 项）
修复后：判定 ✅ 很像 AI Drama Studio 工程包（特征 7 项命中，业务指纹 ✅，无负面信号）
```

同时加了**业务指纹必要条件**（不叫 drama/短剧 的包不给 `pass`），并让负面信号输出具体文件名举例（如 `vendor-monaco-DvmAM2Rn.css`）。负样本回归仍为 `❌ fail` + 3 项负面信号。
